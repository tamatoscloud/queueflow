# QueueFlow — Entity Relationship Diagram

Source of truth is `backend/prisma/schema.prisma`; this document is a
human-readable view generated by hand from it. If the two ever disagree,
the schema wins — regenerate this file's diagrams rather than editing the
schema to match stale documentation.

For the reasoning behind each modeling choice below, see
[`DATABASE_DESIGN.md`](DATABASE_DESIGN.md).

## 1. High-level tenant ownership

Every table below carries `businessId` directly (see
`DATABASE_DESIGN.md` § "businessId-everywhere"). This diagram omits
scalar fields to show ownership/cardinality only.

```mermaid
erDiagram

    BUSINESS ||--o{ BRANCH : owns
    BUSINESS ||--o{ USER : employs
    BUSINESS ||--o{ ROLE : "defines (custom roles)"
    BUSINESS ||--o{ QUEUE : owns
    BUSINESS ||--o{ CUSTOMER : owns
    BUSINESS ||--o{ QR_CODE : owns
    BUSINESS ||--o{ NOTIFICATION : sends
```

## 2. Staff, roles & access

```mermaid
erDiagram
    BUSINESS ||--o{ USER : "employs (businessId NULL = platform admin)"
    USER ||--o{ USER_ROLE : has
    ROLE ||--o{ USER_ROLE : "assigned via"

    PERMISSION ||--o{ ROLE_PERMISSION : "granted via"
    USER ||--o{ USER_BRANCH : "granted access to"
    BRANCH ||--o{ USER_BRANCH : "grants access via"

    ROLE ||--o{ STAFF_INVITATION : "pre-assigns"

    USER {
        uuid id PK

        string email "unique (partial, active only)"
        string passwordHash
        enum status

        uuid id PK
        uuid businessId FK "nullable = system role"
        string name "unique per business or globally per system"
        bool isSystem

        uuid id PK
        string key UK "e.g. queue:operate"
        string category
    }
    USER_ROLE {
        uuid userId FK

    }
    USER_BRANCH {
        uuid userId FK
        uuid branchId FK
        bool isPrimary
```

## 3. Queue operations — the QR-to-served flow

This is the schema backing the product flow in `PROJECT.md`: QR scan →
landing page join → live tracking → staff calls → served → feedback.

```mermaid
erDiagram
    BRANCH ||--o{ QUEUE : hosts
    QUEUE ||--o{ QUEUE_TOKEN : issues
    QUEUE ||--o{ QUEUE_ENTRY : contains
    QUEUE_TOKEN ||--|| QUEUE_ENTRY : "identifies (1:1)"
    CUSTOMER ||--o{ QUEUE_ENTRY : joins
    QUEUE_ENTRY ||--o| FEEDBACK : "requests (1:1)"
    QUEUE_ENTRY ||--o{ NOTIFICATION : triggers
    QR_CODE }o--o| QUEUE : "deep-links to (nullable)"
    BRANCH ||--o{ QR_CODE : hosts
    USER ||--o{ QUEUE_ENTRY : "calls (calledByUserId)"
    USER ||--o{ QUEUE_ENTRY : "serves (servedByUserId)"

    QUEUE {
        uuid id PK
        uuid branchId FK
        string name
        string prefix "e.g. A -> A-023"
        int lastTokenNumber "atomic counter"
        enum status
    }
    QUEUE_TOKEN {
        uuid id PK
        uuid queueId FK
        int tokenNumber
        string displayCode "A-023"
        date issuedDate "daily reset scope"
        enum status "ISSUED | VOID"
    }
    QUEUE_ENTRY {
        uuid id PK
        uuid queueId FK
        uuid customerId FK
        uuid queueTokenId FK "unique (1:1)"
        enum status "WAITING|CALLED|HOLDING|SKIPPED|COMPLETED|CANCELLED|NO_SHOW"
        enum source "QR_LANDING|STAFF_MANUAL|WALK_IN"
        int partySize
        enum notificationPreference "WHATSAPP|SMS|BOTH"
        int estimatedWaitMinutes
        int actualWaitMinutes
    }
    QR_CODE {
        uuid id PK
        uuid branchId FK
        uuid queueId FK "nullable = branch-level chooser"
        string code UK
        bool isActive
    }
    CUSTOMER {
        uuid id PK
        uuid businessId FK
        string fullName
        string phone "unique per business (partial index)"
        bool isBlacklisted
    }
```

## 4. Notifications & feedback

```mermaid
erDiagram
    CUSTOMER ||--o{ NOTIFICATION : receives
    QUEUE_ENTRY ||--o{ NOTIFICATION : "relates to (nullable)"
    NOTIFICATION ||--o{ NOTIFICATION_LOG : "attempted via"
    QUEUE_ENTRY ||--o| FEEDBACK : requests
    CUSTOMER ||--o{ FEEDBACK : submits

    NOTIFICATION {
        uuid id PK
        uuid customerId FK
        uuid queueEntryId FK "nullable"
        enum channel "WHATSAPP|SMS|EMAIL"
        enum type "QUEUE_JOINED|POSITION_UPDATE|ALMOST_YOUR_TURN|YOUR_TURN|..."
        enum status "PENDING|QUEUED|SENT|DELIVERED|FAILED|CANCELLED"
        json payload
    }
    NOTIFICATION_LOG {
        uuid id PK
        uuid notificationId FK
        int attemptNumber
        enum provider
        enum status "SENT|DELIVERED|FAILED|BOUNCED|READ"
        string providerMessageId
    }
    FEEDBACK {
        uuid id PK
        uuid queueEntryId FK "unique (1:1)"
        uuid customerId FK
        enum status "REQUESTED|SUBMITTED|SKIPPED|EXPIRED"
        int rating "1-5, nullable until submitted"
        string comment
    }
```
